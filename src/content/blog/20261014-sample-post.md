这是一篇**示例文章**，存在的唯一目的是把版式压到极限：中文长段落、多级标题、代码块、表格、引用、列表、图片和外链都塞进来，这样任何版式问题都藏不住。定稿后会替换成真实内容。

## 为什么先做减法

这个站点的起点不是一张白纸，而是别人一个 526 个文件的开源模板。真正的工作量不在"写",而在"删"——把 49 篇文章、18 个英文页面、一套私有依赖、一个终端模拟器和一个数据库连接全部请出去，最后留下能支撑五个板块的骨架。

删减完成后，仓库从 526 个受跟踪文件降到 189 个。这个数字本身不重要，重要的是**留下来的每一个文件我都能解释它为什么在**。

### 一个具体的例子

模板里有一个叫 `data-pagefind-body` 的属性。它看起来只是给搜索加个标记，实际上会让 Pagefind 进入"忽略所有没有这个标记的页面"的模式。也就是说，只要有一页标了它，其他没标的页面就会**静默地完全搜不到**——不报错，不警告，搜索结果里就是没有。

这类问题不会在构建时暴露，只会在某个下午你发现"为什么搜不到我的笔记"时暴露。

## 内容模型的取舍

三个集合的分工按**主题**而不是**长度**来切：

| 集合 | 收什么 | 长短 |
| --- | --- | --- |
| Blog | 非产品主题的完整长文 | 不限 |
| Product | 产品主题的拆解、需求、设计取舍 | 长短不限 |
| Notes | 短、快、可能没写完的记录 | 短 |

字段则是统一的：

```ts
const schema = z.object({
  title: z.string(),
  description: z.string(),
  pubDate: z.coerce.date(),
  updatedDate: z.coerce.date().optional(),
  tags: z.array(z.string()).default([]),
  draft: z.boolean().default(false)
})
```

用 `pubDate` 而不是模板原本的 `publishDate` 或 `date` —— 同一个概念在两个集合里有两个名字，是纯粹的记忆负担。

> 设计不是把东西加上去，而是决定什么东西不配进来。

## 还没解决的事

有几件事我明确知道还没解决，把它们写下来比假装不存在要好：

1. 部署平台没定，因为默认域名在国内的可达性需要真机测试
2. 首页只做了中性骨架，没有任何视觉决策
3. 评论、浏览量、双语全部砍掉，但它们随时可以加回来

如果你对其中任何一条有不同意见，欢迎[到 GitHub 上开个 issue](https://github.com/b00ml)。

一篇用来压测版式的文章，写到这个长度刚好能看出行高和段间距是否舒服。

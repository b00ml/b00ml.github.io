学了两个月 Agent，我一开始认定「什么都能干」才叫厉害。后来发现，凡是靠底层模型的能力撑起来的东西，模型一升级就重新洗一次牌。这篇是我把这件事想清楚的记录。

## 一、先撞上的是两个反差

Manus 算是通用 Agent 的招牌：7500 万美元融资、5 亿美元估值，发布那阵我身边不少人排队等邀请码。但真拿它做复杂任务，经常卡住，社区里的评价慢慢变成「又慢又贵」。据报道，热度维持了大约 130 天，随后开始收缩，四个月裁掉了三分之二。

OpenAI 自己的 GPT Store 是同一个剧本。2024 年初上线，攒下三百万个自定义 GPT，绝大多数没人用。到 2025 年 10 月的开发者大会，OpenAI 用 Apps SDK 和 AgentKit 把它换掉了——「做个小 GPT」这件事，平台自己能干，不需要生态来干。

反过来看只做一件事的公司：法律领域的 Harvey 估值 80 亿美元，做代码编辑器的 Cursor 到了 290 亿。2026 年 9 月，Kimi 交出的第一个行业方案也不是通用助手，而是金融 Agent：接了十多个权威数据源，把尽调、合规这一类动作拆成可以直接调用的 Skill；法律侧的 Harvey 干脆基于 Kimi 的模型，训了自己的法律专用模型。

同一条赛道，两种命运。如果这只是运气，也太整齐了一点。

## 二、通用能力不是我的，是模型的

我最初有个错觉：接了模型 API、写了一堆工具调用、调通了提示词，这个东西就「是我的」了。

不是。通用 Agent 的能力，几乎全部来自底层模型。我会调接口，别人也会调；我攒的提示词和工作流，模型公司下个版本做成原生功能，就没了。AgentKit 是个现成的例子：工具调用、评测、界面一次给全，我手工搭的那层「胶水」立刻变成平台的默认功能。

这和我之前写的一点对上了：能被「说得清」再复刻的东西，都在变便宜——代码、界面、提示词、工作流，全是比特，一夜就能被别人重做一遍。那我一个普通人去跟模型公司拼「谁的助手更聪明」，就是拿鸡蛋碰石头。

想明白这点反而松了口气：我根本不该在「通用智能」这条线上跟人比。

说句公道话，通用 Agent 不是没价值。它是最快的验证方式，也是最便宜的入口。但如果一个产品的全部卖点是「比原生 ChatGPT 多会几个工具」，那它就是一个等着被平台吸收的功能，不是一门生意。

## 三、客户付钱，买的不是聪明，是「事办完了」

我以前理解产品，停留在「回答得好不好」。看了些 B 端案例之后才发现，掏钱的人根本不测你的智商。

比如企业拿通用聊天工具去审发票，卡在哪儿？不是模型笨。是这件事天生带领域性：它得知道这张票该进哪个系统、按哪条规则审、谁签字、错了怎么追溯。这些东西没有任何一条写在模型的训练数据里，只能由熟悉这家公司的人一条条喂进去。

我印象最深的一个细节：真正跑通的垂类产品，做的是「端到端把事做完」，而不是「在旁边帮你」。采购 Agent Ranger，你说一句需求，它自己去寻源、审合同、接供应商、做风险评估、配发票审批，不是帮你写一封采购邮件。国内零犀在保险销售里，甚至跑通了全程不靠人介入的闭环。

回头看我自己做过的两个小项目——一个知识工作台、一个英语内容生产工作台——走的也是这个路子：不是「帮你写点东西」，而是把「抓到内容 → 转写 → 总结 → 落盘 → 以后还能被检索到」这条链跑通。当时全凭直觉，现在才反应过来，这大概就是垂类闭环最朴素的样子。

Copilot 和 Agent 的区别，我是在这儿才分清的：前者是「我辅助你」，后者是「这事交给我」。前者卖效率，后者卖结果。

## 四、能攒下来的，是三层东西

如果我还要往这个方向做，真正能留下、别人抢不走的，大概就三层：

| 层 | 具体是什么 | 模型变强之后 |
| --- | --- | --- |
| 领域上下文 | 专有数据、业务规则、合规要求、历史决策 | 冲不掉。同样的新模型，只有我知道该喂什么 |
| 工作流闭环 | 从输入到交付的整条流程、审批点、出错怎么回滚 | 流程不用动，只换引擎 |
| 结果与信任 | 输出稳定、可追溯，敢按结果收费 | 越贵的东西越需要它，而它只在场景里长出来 |

最底下那层是我之前写过的「上下文资产」，只不过这次它长在一个具体行业里：这些东西不在网页上，不在训练集里，是一天天用出来的。

有一句话我抄在了笔记上：垂类产品不会在「原始推理」上赢过前沿模型，它占住的是**通用模型和一个真实工作流之间缺的那一层**——哪些文档算权威、Agent 能碰哪些系统、每一步过什么检查、谁拍板。正因为占住了这一层，以后换更强的模型，整套工作流不用动。

这句话让我安心，也让我看清了分工：模型公司供应基础能力，垂类供应「这一行到底怎么干活」。两边不是敌人，是接在中间。

但它不是一张保票。垂类也会死：死在太窄，只做一个别人三天能抄的功能；或者死在太软，没真正嵌进流程，永远停在「帮你想想」。护城河是方向，不是结论。

## 五、于是我给自己定了五条笨规矩

谈不上方法论，就是接下来打算这么做：

- **每加一个功能，先问它是补模型的短板，还是在攒自己的资产。** 如果一年后模型升级，这个东西自动变得多余，那就是短板；如果它变得更值钱，那才是资产。
- **别问「我要做个什么 Agent」，问「我想把哪件事办完」。** 一问「做个助手」就容易贪多，一问「办完哪件事」，范围立刻收窄。
- **从轻的地方开始。** 能力是分层的：先用 Hook、Skill 这种小的把一个小场景跑通、拿到真实反馈，再考虑加 MCP、Plugin，最后才轮到独立产品。一上手就搭大系统，是我最容易踩的坑。
- **动手前先回答：谁来判断我做得好不好？** 测试集、真实用户反馈，还是我自己每天在用？答不上来，大概率是在自嗨。
- **先多用。** 代码的、客服的、内容的，不同类型的 Agent 我都逼自己真刀真枪用够——用多了才知道人到底卡在哪一步。

## 写在最后

写这些不是什么大道理，就是我这段时间学习的一次阶段性收口。

我原来以为学 Agent 就是追最新的模型、最酷的框架。现在越来越觉得：模型会一直变强、一直变便宜，这部分我再怎么学也追不上大公司。我这种人真正能攒下的，是在一个具体场景里，一天天用出来的上下文、跑顺的工作流，和被结果验证过的信任。

「什么都能干」听着很性感，但我不打算去做了。我更想做那个——在某一件小事上，事交给他，你放心的人。

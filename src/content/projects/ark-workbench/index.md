## 它解决的是哪个问题

我的笔记散在 Obsidian 里，用了几年，问题是同一件：**写得进去，取不出来**。模型每次对话都从零开始，三个月前为什么这么判断、当时否掉了哪个方案，一句也接不上。

现成的做法是再买一个「第二大脑」，把资料搬过去。我没有这么做——搬过去之后，笔记的真源就不再是我自己的 Markdown 文件，而是一家公司的数据库。Ark 的取舍相反：**Vault 里的 Markdown 永远是唯一真源，其余全是删掉能重建的派生物。**

于是它要同时回答三件事：

1. **收集**——视频、文章、邮件里的链接丢进去，出来一条带来源、能检索、能引用的结构化笔记。
2. **接续**——这次在 Obsidian 里聊到一半，下次换 Claude Code 或手机 QQ，能接着上次的假设往下想，不用重述背景。
3. **复用**——把结论送出去（发邮件、发消息），但送出去之前得有人点头。

三条共用一个大脑：本机只跑**一个** `ark serve` 进程（`127.0.0.1:8650`），所有宿主、所有设备都连它。不是在各设备之间同步状态，而是根本没有第二份状态。

## 五条硬约束

系统里只保留五条不能破的约束，其余全交给「事后能撤销」兜底。这不是安全清单，是设计边界：**凡是 Git 管得住的地方，就不设审批。**

1. **原始素材只读。** `raw/` 之类的目录由路径守卫强制拒写——原始素材丢了，谁也重建不出来。通用工具同时拒绝一切点开头路径（`.git/`、`.ark/`、`.env`）、根目录的 `ark.toml` 与 `ark/` 状态目录，`write`/`patch` 只写 `.md`。
2. **每一次 Vault 写入都可撤销。** 一次用户操作、一次插件请求或一次定时任务运行，期间所有写入合成**一个** Git 快照，提交信息带来源（`ark(<source>): <操作> <路径>`）。快照的单位是操作，不是工具调用。
3. **外部写动作执行前必须确认。** 发邮件、发消息、对外发布 git 撤不回来，所以只有这一类走事前确认；定时任务在启用时一次性授权，外部宿主调用时由宿主自己负责审批。
4. **Ark 自己的模型调用有预算。** 单次会话与每日 token 双上限，覆盖自带 Agent 的回环、记忆抽取和插件里的模型调用。外部宿主自己的模型调用由它自己记账。
5. **凭据只放 `.env`。** 不进仓库、不进 Vault、不进日志。

## 本地跑起来（依赖就绪后 5 步）

前置：Python 3.11+、Git、一个已有的 Obsidian Vault。开机自启是可选第 6 步，不计入。

1. **初始化**：`ark init <vault>`（Python 包形态下是 `python -m ark_core init`）在 Vault 根生成 `ark.toml`、`mcp.json` 与 `.env`（含随机 Bearer token），并给还不是 Git 仓库的 Vault 建一个仓库。
2. **填配置**：`ark.toml` 里写 `vault`、`readonly = ["raw/"]`、`[core] listen`、`[model] chat`/`extract` 与两处预算；模型 API key 放进 `.env`。配置只有三个文件，程序不改写 `ark.toml`。
3. **启动服务**：`ark serve` 起单个常驻进程，`/mcp` 是 MCP Streamable HTTP，`/v1` 是 OpenAI 兼容的 SSE 与动作确认接口；确认 `/mcp` 有应答。
4. **装 Obsidian 插件**：插件里填地址与 `ARK_TOKEN`，四个面板（对话 / 历史 / 记忆 / 设置）用同一套 Core 工具，不经 Agent 回环也能用。
5. **接第二个宿主**：Claude Code 用 `.mcp.json`、DSH 用 Cordis YAML 条目，指向同一个 `/mcp` 并带上 `Authorization: Bearer`，然后问一个只读问题，看它是否带出处、资料不足时是否直说。

只想把它当 MCP 服务用时，第 4 步可以跳过——不启用 Agent 和插件，进程只提供 Core 工具。

## 四篇工程深读

总览说「是什么」，这四篇说「为什么这么做」和「哪一步出过错」：

- [v1 → v2：一次做减法的重构](/projects/ark-workbench/v1-to-v2)：为什么删掉逐次写审批和那几套各自为政的账本，改成 Vault 内免审批直接写 + Git 按操作单快照，只给不可逆的外部动作留事前确认。
- [多渠道共享大脑与上下文工程](/projects/ark-workbench/multi-host-and-context)：单进程同时暴露 `/mcp` 与 `/v1`，连自带 Agent 也只经 MCP 调内核；桌面三宿主、手机 QQ、邮件端的协同拓扑，2k/4k 双层预算，以及 `rev`/`base_rev` 把过期写入逼进 `.pending` 的并发规则。**每条渠道都标了它停在哪一级证据上。**
- [记忆防污染与插件契约](/projects/ark-workbench/memory-and-plugins)：`inferred` 与 `confirmed` 的数据隔离、确认通道 `via` 与按通道一键降级，以及「插件数据只放 Vault Markdown、不建私有库」的硬契约。
- [观测与回归双闭环](/projects/ark-workbench/eval-loops)：轮次轨迹怎么落盘、怎么升格成二元 Rubric 用例、门禁脚本怎么在 pre-push 与 CI 上守住「以前能用的现在还能用」。

## 适用范围

单人、本机 Vault、自己的模型配置。不做团队协作、不多端同步状态、不做账号体系——加了这些，`raw/` 只读和「一台机器跑大脑」这两条就得先拆掉，那已经是另一个产品。

Obsidian 移动端暂不适配：多端先覆盖的是不同 Agent、QQ 和邮件这些渠道。手机里看笔记用 Obsidian 自己的同步就够，接续思考要等回到主机。

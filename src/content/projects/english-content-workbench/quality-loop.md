## 先把生成的输入端收紧

每种题型一张模板，写清输入字段和输出结构。任务创建时存一份配置快照，之后改模板不影响已经在跑的任务。

输出走 JSON 模式，不是约束解码：模型只能选「要不要给一个 JSON 对象」，不能选「这个字段只能是 A/B/C/D」。结构得自己兜——动态 Pydantic 描述结构、取回对象、解析展平、生成 JSON Schema、跑跨字段规则，不通过就带着校验信息重试，次数耗尽抛错。

跨字段规则每条背后都错过一次：每题恰好四个非空不重复的选项，不带「A.」前缀；答案只能是 A/B/C/D 并映射到选项下标；完形 blanks 从 1 起连续，passage 里 `____` 数等于 blanks 数；阅读的 evidence 落在给定范围内。

五题以上答案全在同一位置时只告警、不重排——重排会把答案和解析一起拧错。

## 规则判什么，模型判什么，人判什么

| 层 | 判什么 | 判不了什么 |
| --- | --- | --- |
| 规则 | 结构、字段类型、选项数量与重复、答案取值域、完形空数与标记是否对齐、evidence 范围 | 答案对不对、选项之间是否说得通 |
| 模型 | 语感、干扰项质量、解析够不够用、难度是否贴合 | 教材原文里的事实、答案是否唯一 |
| 人 | 答案正确与唯一、解析是否与答案矛盾、引用是否真支撑这条规则 | 逐题重看（成本上做不到） |

规则层让确定的错不花 token，模型层只给一个可比的分数，人层收机器判不了的。

## 分数怎么算

每维度 0～100 分，两轮成功采样、每轮最多 3 次无效尝试，按维度取均值再按权重加权：sum(d_i × w_i) / sum(w_i)，过 70 自动通过。阈值全局，也能覆盖到维度或模板——阅读的解析比单选更吃语感，同一个 70 不是一个意思。

两次采样差十几分很常见，所以分数只当筛选器，不当判据。

## 标黄，我最后没走灰区

原设计有条灰区：自动过了但分落在区间内，内容置待复核、工作流在检查点中断等人。机制和校验都在，我把三种内置模板的灰区开关全关了。

真正强制人工的不是分数区间：内容带检索引用时，来源核验是必填，缺一条走不下去。关掉之后所有内容都落待复核，更简单也更难绕过；代价是那段成了死代码。

## 样本

人审通过或发布的内容可显式存样本，同一条再存不新增记录，按条目 id 幂等。样本分候选、已核验、种子三级，工作流只取已核验。

few-shot 样本拼进生成请求，最多 2 个完整例子、额外 8192 字符封顶。这栏现在是 0 条：链路和开关都在，库里没东西，等于没被真实样本走过。

## 现在的问题

- 6 条真实内容的自动分在 87.70～91.75，复核仍挑出完形正确项全挤在 A、几个连词空有多解。
- Judge 和生成是同一个模型，两轮采样压不掉同模型自偏好。
- 驳回率没有分母。内容表的分数是可变的业务字段：通过写当轮分、失败写 0、人工通过覆盖成 100、驳回写 0，真实自动分只在质检记录里；失败和没入库的轮次又在另一张表。
- 口径 2026-08 收窄过一次，旧版把答案长度异常、位置异常、自指歧义都放过了，旧通过率不能直接比。

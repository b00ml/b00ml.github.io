## 这个场景为什么难自动化

一家制造企业的财务审核，我接触到的三条链路：差旅报销、发票稽核、银行对账。规则多、留痕要求高、错一次要返工。

真正让自动化卡住的不是规则多，是另外三件事。制度里有一半条款写的是「原则上」「视情况」，那不是判断句，读不出真假。证据在扫描件里，不在数据库里。同一笔支出可能拆成几张票、跨几个月，单看每张都合规。

所以我一开始就否掉了一个做法：让模型读完单子，直接给「通过」或「驳回」。说不清依据的「通过」，审核员只能重看一遍。

## 分工：四层，越往下越不敢交给机器

| 角色 | 负责什么 | 明确不能做什么 |
| --- | --- | --- |
| 规则引擎 | 把能写成判断的条款全量跑一遍，差旅这边 11 类检查 | 处理语义判断 |
| OCR | 把票面金额、抬头、税号、票号、日期落到字段 | 判断这张票该不该报 |
| LLM | 独立给一次第二意见，或给分歧单子写调查摘要 | 改变单据审批状态 |
| 人 | 最终放行或驳回 | — |

这张表的最后一列是硬的，不靠提示词自觉。调查 Agent 的工具注册表里没有任何一个写接口，模型想改状态也没有入口。

系统可以回写审核意见，但回写的只是意见。ERP 里的单据审批状态，从头到尾只有人能改。

## 三条链路各自跑到哪一步

M2 差旅审核是最完整的一条：读 PENDING 单、拉附件、本地 OCR、规则跑 11 类、可选模型复核、分歧转 FLAG、回写意见。图模式下还能开调查 Agent 和人工 gate。

M3 发票稽核是规则扫全量兜底：重复票、抬头、税号、税率、连号、供应商档案。AI 复核在这里只输出 CONFIRM、DOUBT、FALSE_ALARM 三种意见，AI 全量巡检只产疑似清单。

M4 银行对账最难：一笔流水可能对应多张发票，也可能只付了一部分，组合搜索有预算上限，超了交人认领。

三条的判定逻辑差别很大，分开写在[三条业务链路](/projects/finance-review-agent/workflows)。

## 三个取舍

**宁可标黄也不猜。** 规则和模型不一致，转 FLAG；证据不足、OCR 失败、城市不在标准表，也转 FLAG。FLAG 不是异常状态，是正常产物。裁决节点只允许把结论往人工关注的方向推，不往回走。

**证据链优先于准确率。** 每条调查证据要绑定 call_id、来源 ID 和字段路径，落不了地就判失败、结论降级为存疑。我宁可少一条证据，也不留一条说不清出处的。

**不做端到端黑箱。** 给审核员的是「这里可能有问题 + 依据」，不是一个结论。全信模型他要担责，全不信等于重做；只有给到具体疑点，那一步才算省下来。

这三条背后的机制写在[分工与边界](/projects/finance-review-agent/boundaries)里。

## 现在到什么程度

代码是齐的：前端、API、规则、OCR、检索、Agent 图、任务队列、对账，都在。单测、API 契约、离线评测和前端构建都在 CI 里跑。用一份 23,461 张发票的台账扫出 42 组重复票和 135 项票面问题，315 笔银行流水匹配上 201 笔。

但这些数字的边界要说清楚，否则容易被读成准确率：多数是资料口径和离线合成集上的结果，不是盲测。我把口径逐个列在[工程与验证](/projects/finance-review-agent/engineering)。

## 没做到的

这个 POC 明确不承诺几件事，原因不是来不及，是优先级。

身份认证、RBAC、多租户没做。它现在要回答的是「机器能不能给出可审计的审核意见」，不是「能不能给十个财务同时用」。先加权限要花两周，而这两周不产生任何关于审核质量的新证据。

消息队列和高可用 worker 也没有。单节点 SQLite 够跑几十单；上 MQ 要先解决重复投递和幂等，那是吞吐问题的解法。

生产密钥托管同样欠着。ERP 连接信息现在在 .env 里，前端 POC 还可能把它写进 localStorage。这块必须改，但在只有我一个人拿合成数据跑的时候，先修它等于先修一个还没有用户的 bug。

最实质的缺口是真实运行态：整条链路没有在真实 ERP 上跑过。有一次真实的模型调查冒烟跑通了——2 步、8 次工具调用、14,602 tokens，6 条证据里 4 条通过来源回溯。这只证明链路转得动，不证明所有单据都是这个成本。

下一步我先做三件事：后端凭据托管和用户权限、300 单规模下的端到端性能与失败基线、人工裁决真值的积累。

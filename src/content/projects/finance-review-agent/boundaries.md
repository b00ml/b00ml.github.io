## 规则能写到哪一步

判断句能落地，前提是字段可枚举、比较关系确定。

差旅这边我写成了 11 类检查：住宿标准、伙食补助、市内交通、长途舱位、发票抬头、税号、金额、重复发票、加班打车的事前审批、缺附件、科目归集。每一条都能说成「取哪几个字段、和哪个标准比、超了报哪个违规码」。

写不进去的是另一类：「住宿地点和行程是否匹配」「一张单拆成三张是不是为了压额度」。制度里写的是原则上、视情况，要读懂整张单子才能判断，没有确定性算法。

分界线很土：能用字段加比较关系说清的，写规则；说不清的，不进规则，交给人。

规则也会承认自己判不了：OCR 拿不到票面、附件不可用、城市不在标准表里，这几种情况不兜底成默认值，直接进人工关注。这是规则内部的标黄。

## 模型为什么只能当第二意见

财务规则的第一个要求不是聪明，是稳定：同一个输入，今天和明天同一个结论，出错了改一行代码就能修。LLM 做不到——同一张单子跑两次，可能给两个措辞，甚至两个判断。所以它的位置被压窄了：独立跑一遍，和规则结论比对。一致，什么都不做；不一致，转 FLAG，由人裁决。

它不是「再审一遍」，是「对规则提异议」。它没有推翻规则的权力，只有让单子变黄的能力。

代码里有两处硬实现：裁决节点拿到 suggest_approve 时，当前结论若不是 FLAG 会防御性升级成 FLAG；模型复核调用失败、解析失败或超时，直接回退规则结论，不会因为模型没说话就默认通过。

## 标黄不是异常，是产物

FLAG 跟 APPROVE、REJECT 平级，不是错误码。进 FLAG 的路径有好几条：规则和模型分歧、证据不足、OCR 失败、城市不在标准表、M4 里无法安全匹配、调查工具超时或预算耗尽。

| 情况 | 系统怎么做 |
| --- | --- |
| 规则命中且有票面证据 | 给结论，附违规码和证据字段 |
| 规则没覆盖，票面完整 | 给规则结论；模型复核一致则不动，不一致转 FLAG |
| 证据落不了地 | 这条证据判失败，结论降级为存疑 |
| 调查失败或预算耗尽 | 生成降级报告，往人工关注方向收敛，不中断整批 |

关键在最后一行：不管中间跑了多少步、调了多少次工具，结论只会往人工关注的方向收敛，不会因为多跑几步就变回通过。这条是防「模型越努力越容易放过」的。

开了图模式和人工 gate 之后，interrupt 会暂停并保存 checkpoint；人提交决定时带 expectedRevision，对不上返回 409，避免重复提交互相覆盖。

## 证据落不了地，结论就得降

每条调查证据带三样东西：call_id、来源 ID、字段路径。校验三件事——工具调用真实存在且成功、来源 ID 出现在那次调用的返回里、字段路径能走到底。

对不上就标记失败。结论依赖它、而它又不是「建议交人关注」这一类，结论降级为存疑。

一次真实冒烟里，模型给了 6 条证据，4 条通过来源回溯，2 条被拦下。比例不好看，但这就是代价：宁可少一条证据，也不留一条查不到出处的。

要说清的是，grounding 做的是来源和字段绑定加启发式回溯：它能拦住编造的引用，但证明不了结论在语义上对，也判断不了制度条款是否适用于这单业务。这一点我没有更好的办法。

## 为什么不做端到端黑箱

如果模型直接给结论，人只有两个动作：全信或全不信。全信要担责，全不信等于从头看一遍，那这一步就没省下来。给疑点和依据，人才能只看看得懂的那几处。

反过来也成立。说不清依据的正确结论，在审计面前等于没有——审计要的是可追溯，不是准确率。

代价说直白些：这套东西省的是「翻找」，不是「判断」。我没法证明它把总工时降了多少。

## 卡点

两个我认的缺口。

一是标黄的正确率没有真值。FLAG 转人工之后人怎么判、判得对不对，目前没有系统化收回来。没有这批真值，「标黄标得准不准」就只靠个案感觉。

二是制度里那些「原则上」的条款，现在仍然靠人看。规则和模型都覆盖不了，我也没有把握说下一版能覆盖。

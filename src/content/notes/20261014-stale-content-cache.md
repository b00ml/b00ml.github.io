把一个 526 文件的开源模板删到 189 个文件之后，我用"扫描 `dist/` 里有没有残留的 `joye`、`waline`、`jojo`"来验收。这个判据看起来无懈可击——直到它漏掉了两个页面。

## 症状

删掉 `dist/` 重新构建，页面数没变。清掉模板作者的内容目录，页面数还是没变。这两个页面在 `src/content/` 里**根本不存在对应的文件**。

它们是早先做搜索验证时留下的临时文章，源文件清理时被删了。但每次构建，它们照常生成。

## 原因

Astro 5 的内容层把集合条目缓存在 `node_modules/.astro/data-store.json`。glob loader 在重新加载时**会新增、会更新，但不会删除源文件已经消失的条目**。

所以删文件这件事对构建是不可见的。构建读的是缓存，缓存里那条还在，页面就还在。删 `dist/` 没用——问题不在输出侧。

## 为什么我的验证没抓到

我扫的是 `dist/` 里的**字符串残留**。这两个幽灵页的 slug 是中性的 `temp-note`、`temp-product`，正文里也没有任何作者标识。字符串扫描对它们完全无感。

**用字符串扫描验收"删除是否彻底"，只能覆盖靠字符串识别的东西。** 它抓不到"多出来的东西"，只能抓到"留下来的东西"。

正确的验收对象是**路由清单和页面数**：删之前记下有哪些页面，删之后逐条比对。数量对不上，具体是哪个页面多出来的，一眼就能看出。

## 修法

构建前清空内容层缓存：

```js
// scripts/clean-content-cache.mjs
import { rmSync } from 'node:fs'
rmSync('.astro', { recursive: true, force: true })
rmSync('node_modules/.astro', { recursive: true, force: true })
```

挂在 `build` 前面。代价是每次构建多几秒、丢掉增量缓存，换来的是"文件删了页面还在"这一类问题从此不可能发生。

顺带一提，`node_modules/.astro/assets/` 里还留着已删除源图的压缩衍生图（webp）。同一类问题，同一个修法。

## 更一般的教训

**缓存不失效是不会报错的。** 它只会让构建成功、输出合法、然后发布一个不该存在的东西。这类缺陷没有任何信号——没有警告，没有非零退出码，本地预览也完全正常。

所以我倾向于把这种清缓存动作做成**无条件的**，而不是"记得在删内容后手动跑一次"。需要记得做的事，早晚会忘。

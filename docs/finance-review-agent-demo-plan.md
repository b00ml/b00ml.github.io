## 1. 目标与体验

访客在博客 `/projects` 页看到「企业财务审核 Agent」卡片，点击右侧的「Demo 体验」，
进入一套可以操作的完整财务审核工作台。访客应能理解报销审核、发票稽核和银行对账的实际操作流程。

Demo 以现有 POC 的 Vue 前端源码为基础，保留原页面结构、侧栏、表格、详情、证据对比与复核交互。
原型截图用于视觉校验；当截图与当前源码存在差异时，以当前源码的页面和功能为准。

## 2. 入口、路由与工作台外壳

入口页继续使用博客现有的布局与配色。卡片正文仍链接项目介绍，Demo 按钮作为其旁边的独立链接，
不能放入卡片的 `<a>` 内。桌面端按钮位于卡片右侧；窄屏时按自然文档顺序移到下方。
其他项目卡片保持现有行为。

Demo 入口为 `/projects/finance-review-agent/demo/`，进入后默认打开 M2。
工作台保留原 Vue 前端独立的视觉风格，不加载博客页头或博客全局样式。
顶部常驻提示「虚拟数据演示 · 审核、AI 复核与对账使用预置结果」，并提供「返回项目」链接。
侧栏显示「演示数据已加载」，不能把虚拟连接写成「已连接 ERP」。

子应用采用 Vue Router 的 hash 路由，内部地址示例：

```text
/projects/finance-review-agent/demo/#/m2
/projects/finance-review-agent/demo/#/m2/DEMO-0001
/projects/finance-review-agent/demo/#/m3
/projects/finance-review-agent/demo/#/m4
/projects/finance-review-agent/demo/#/settings
```

子路由留在 hash 内，静态宿主只需返回同一个入口文件；不依赖服务器 rewrite 或 SPA 404 回退。
Demo 的入口斜杠来自独立静态目录，不修改博客全局 `trailingSlash: 'never'`。
构建时避免与 Astro 项目文章路由重复生成同一个文件。浏览器前进、后退及详情页刷新都要可用。

| 公共外壳 | `App.vue`、`components/SideNav.vue`、`style.css`                              | 保留原工作台结构，增加演示标识、返回入口和窄屏导航                             |

### M2：体验一张报销单的审核

1. 初次进入展示待审单据，统计与数据保持一致；未审核时不提前把所有单据显示为已出结论。
2. 勾选单据并执行审核，短暂展示处理状态，再显示选中单据的预置结果。
3. 在详情中查看 OCR 字段、系统字段、违规依据，以及预置的 AI 第二意见。
4. 选择人工结论并填写备注，提交到当前页面的内存状态。
5. 返回列表仍能看到本次演示的结果，刷新后恢复初始数据。

列表必须区分 ERP 原始业务状态、机器审核建议和人工复核记录。
人工操作不能覆盖机器建议，也不能把虚拟 ERP 的 `PENDING` 自动改成真实审批状态。
原控件中的「写回 ERP」「不可撤销」「操作将记录至审计日志」等表述应调整为准确的模拟语义。

如保留原有 OCR 字段编辑与确认控件，只更新本地字段及确认状态，并说明预置审核结果不会因此重新计算。
缺附件、缺影像或缺 OCR 的样例应显示对应空态，不能通过通用占位图掩盖缺证据场景。

### M3：从异常线索查看票面与复核理由

保留重复票、票面问题和供应商详情入口。AI 复核输出 `CONFIRM`、`DOUBT`、`FALSE_ALARM` 的
预置意见与理由；全量巡检展示单独的演示清单，不能声称进行了实时模型推理。
三种意见与巡检补充样例需标明为演示编写，不能当成原 POC 实际运行记录。

### M4：展示匹配与无法匹配的边界

沿用原对账页面布局与图表。3 条流水中包含 2 条贷方、1 条借方；演示结果为 1 条匹配、
1 条未识别，借方不参与收款匹配。所有总数、金额、比例和图表取自同一份演示结果。
预置应收项目与别名仅为支持该结果而补充，不扩写一套浏览器匹配引擎。

### 交互共同约定

- 页面显示的数据和可见操作都要有明确结果；不保留点击后永久加载的按钮。
- 审核、AI 复核与对账通过少量处理状态表达流程，不复制服务端长任务、重试与分钟级轮询。
- 未知单据 ID 显示「未找到演示单据」并提供返回列表；未知子路由提供返回工作台入口。
- 原页面支持的复制文本、影像预览继续可用；链接只能指向打包的演示资源或明确的返回入口。
- 全部业务状态位于内存，路由切换不丢失，刷新或重新打开工作台即重置。

## 4. 数据与来源

主数据复制自 `E:\vibe_coding\poc\data\demo\`，随 Demo 一起打包：

| 文件                    | 用途                                       |
| ----------------------- | ------------------------------------------ |
| `claims.json`           | 6 条合成报销单、费用行、附件引用与审批信息 |
| `invoices.json`         | 6 条合成票据，包含重复与票面异常线索       |
| `bank_transactions.csv` | 3 条合成银行流水                           |
| `policies.md`           | 演示政策依据与说明                         |
| `expected_results.json` | M2 与 M4 结果基准                          |

M2 的基准必须保持不变：

| 单据 ID     | 预置机器建议 |
| ----------- | ------------ |
| `DEMO-0001` | `REJECT`     |
| `DEMO-0002` | `REJECT`     |
| `DEMO-0003` | `FLAG`       |
| `DEMO-0004` | `REJECT`     |
| `DEMO-0005` | `FLAG`       |
| `DEMO-0006` | `REJECT`     |

共 4 条 REJECT、2 条 FLAG；不能为了展示绿色状态擅自改成 APPROVE。
人工选择「通过」属于体验者的模拟复核记录，与这份机器建议分别呈现。

上述 JSON/CSV 不是所有前端响应的完整集合。实施时还需补齐页面所需的 OCR 字段、违规理由、
AI 意见、M3 结果、供应商画像、M4 应收项及本地票据影像映射，并注明为补充演示数据。
金额单位沿用源字段约定，`amountFen` / `totalFen` 到展示元的换算只做一次。

票据影像使用本地合成素材并标注「演示票据」，不把原型截图当成可编辑的票面数据。
附件 ID 必须映射到子应用内资源；删除 `/api/erp/attachments/.../content` 这类隐含后端依赖。

复制源码时记录实际 POC 源码版本、带入的本地差异和日期，保留其 MIT 版权与许可文本。
两个仓库分别维护；以后同步采用明确的人工比对，不在博客构建时读取 POC 工作目录或临时拉取远端源码。

## 5. 实现结构与数据边界

以下为建议目录；此文档未创建这些文件：

```text
apps/finance-demo/
  package.json
  bun.lock
  index.html
  vite.config.ts
  LICENSE
  README.md                 来源、启动方式与同步说明
  src/
    App.vue
    main.js                 沿用原入口，按实际需要调整
    router/                 hash 路由
    views/                  原 Vue 页面及必要演示适配
    components/             原公共组件
    stores/                 会话内状态
    api/index.ts            唯一的本地数据适配入口
    fixtures/               合成输入及补充的预置结果
    style.css
  public/                   本地合成票据等资源
scripts/build-finance-demo.mjs
docs/finance-review-agent-demo-plan.md
```

沿用 Vue 3、Vue Router、Pinia、Element Plus 和 ECharts，不把所有 `.vue` 页面重写成 Astro。
博客卡片使用 Astro；新增适配与构建逻辑使用 TypeScript / 仓库现有脚本格式，原 Vue 文件按需修改。

本地适配入口保留页面所需的 `get` / `post` / `put` 调用形状及已解包响应结构，
直接读取合成输入、返回预置结果、更新会话状态。只实现现有页面实际消费的调用，不做通用 mock 服务。

适配覆盖：

- 报销列表、分页形状、详情、审核状态与 OCR 字段。
- 批量审核结果、人工复核记录，以及页面已有的人工 gate 交互所需状态。
- M3 扫描、AI 复核、巡检及其结果。
- M4 对账结果、系统设置状态。

未知调用直接给出可定位的错误，不能回落到真实 HTTP。
子应用使用固定的演示数据入口，不保留面向生产 ERP 的另一套运行分支或可切换 API base URL。
原 `connection` store 的演示初始化可以复用，但仍需移除真实连接和存储读写路径。
现有 `VITE_DEMO_MODE` 只负责过连接门槛，并未覆盖全部 API、附件 URL 和设置存储，因此不能视为完成。

页面加载只请求同域静态脚本、样式、字体和合成素材。
不请求 `/api`、ERP、模型服务或外部字体/CDN，不读取、保存或上传 API Key；
不使用 localStorage、sessionStorage 或 IndexedDB 保存业务状态。

## 6. 构建与博客接入

子应用独立持有依赖清单与锁文件，使用仓库钉定的 Bun 1.3.10。
既有博客依赖树与 `bun.lock` 不因接入 Vue 子应用而重新解算。
子应用新增依赖时固定验证版本并生成其 `bun.lock`，安装使用 `--frozen-lockfile`。

根构建流程调整为：

1. 执行已有 Astro 内容缓存清理与博客构建。
2. 运行 Vue 子应用构建，将 Vite 的 base 指向 `/projects/finance-review-agent/demo/`。
3. 仅向 `dist/projects/finance-review-agent/demo/` 输出子应用，不能清空整个博客 `dist`。
4. 任一步骤失败即终止，成功后 GitHub Actions 继续上传完整 `dist`。

CI 安装步骤增加子应用的冻结依赖安装。构建不联网下载业务数据，也不依赖本机 POC 目录。
生成目录留在忽略的构建产物中，不手工维护一份 `public/` 下的已编译副本。
博客普通文章路由和全站主题配置保持原语义，工作台的 CSS 不注入博客页面。

本地完整体验使用 `bun run build` 后的 `bun run preview`；日常修改 Vue 时可在子应用内单独启动 Vite。
先不增加博客开发服务器反向代理。需验证构建预览与最终静态文件布局一致。

## 7. 适配与可访问性

桌面优先保留原左侧导航、统计卡、列表、详情分栏与弹窗关系，视觉以现有 Vue 页面为基准。
不增加一套博客主题色覆盖工作台；Demo 沿用原工作台浅色样式。

窄屏复用博客既有 640px / 768px 断点：侧栏可收起，表格在自身容器横向滚动，
详情分栏纵向排列，按钮与弹窗不溢出视口。页面本身不能被宽表撑到无法操作。
导航、操作、弹窗支持键盘与可见焦点，抽屉关闭后焦点返回触发按钮。
新增动画遵守减少动态效果偏好，处理状态不能只靠颜色表达。

## 9. 范围、取舍与复杂度检查

本期交付可体验的前端工作流。真实 OCR、规则计算、RAG、Agent 调查与模型调用由预置结果表达，
真实 ERP 接入、生产审批、身份体系、服务端任务系统和跨会话保存均不在本期。
静态 Demo 的结论不是在线业务计算，也不是新增的模型效果评测证据。

最小实现是「原 Vue 页面 + 一个本地数据适配入口 + 一次独立静态构建」。
只放截图无法完成交互流程；继续扩展首页小模块无法复现完整前端；
另起后端增加部署和密钥依赖，因此都不满足本次已确认目标。

按 minimal-design-gate 检查：

1. 结构：在数据边界统一替换后端依赖，避免逐页散落网络回退与真假模式切换。
2. 使用负担：访客不填地址、密钥或运行参数，打开即可体验。
3. 可推导项：单据数量、金额、统计和选中数量从演示状态派生，不手工维护多份展示值。
4. 复杂度：复用原组件和依赖，不增加通用 mock 框架、Service Worker、后端或 Astro Vue 集成。
5. 适用范围：专用于这个财务工作台，直接绑定现有项目标识，不提前设计通用多项目 Demo 平台。

主要维护成本是两个仓库各持有一份 Vue 页面，已在对齐中确认接受。
实施时通过来源记录和聚焦的数据适配降低后续比对成本，不增加自动同步系统。
